# Agent Note: 2026-09-10 two-machine integration — conflict decisions

Status: implemented

English | [中文](2026-09-10-integration-0910-conflict-decisions.zh.md)

## Problem

The `integration/0910` branch merges the fixed upstream target `b2e3b2a012` (0.1.5-alpha.2) into the Mac save branch (`save/mac-0910`, fork of 0.1.2-alpha.1 plus the macOS packaging pipeline, the two-decimal cache display, the version switcher and rewind labels, and the web-search provider fixes), and then merges the hgg save branch (browser 401 token form). The two sides diverged through upstream rewrites of the session controller, the stats UI, and the chat scroll model, so most of the 64 conflicted files needed per-file adaptation of our behavior onto the new upstream structure rather than a side-for-side pick.

## Decision

**Fork commit `756e2c3830` (browser rpc ids without a secure context) is not cherry-picked.** The upstream target carries the equivalent mechanism: `packages/client/connection/src/client/random-uuid.ts` is imported by `src/client/rpc.ts` and `src/client/fixture.ts` (exactly the two files the fork commit patched by other means), and `packages/util/crypto` owns the host-side `randomUUID()`. The merged tree uses the upstream paths; the fork commit's original note stays in fork history as provenance.

**Session controller.** The candidate rewrote `reject(...)` into `throw new RemoteError('session/...')` with branded `SessionSeq`/`SessionLogOffset`/`SessionId`. Our `rewind` fork option was ported into that structure in `commands.ts` (anchor via `findLast` over `turn/start` events, an `emptyRewindChild` for rewinds from the first turn, `SessionLogOffset(0)` cut, and `{ sessionId, blank }` as the return), and kept as an option plus a `blank` summary field in `manager.ts` on the candidate's `RemoteResult` flow. `service.ts` passes `rewind` through the candidate's `SessionSeq(Math.floor(opts.atSeq))` anchor. The host spec asserts child content through `Session.snapshotEvents()` (the candidate accessor) instead of the fork-era `session.events`.

**Stats.** Upstream replaced `StatsLine.tsx` with `StatsPills.tsx` (+ `TurnUsagePanel`, `stat-dialog.ts`). Our two-decimal cache-hit display moved into `StatsPills.tsx` as `roundedHundredthPercent` (half-up, `9_999` cap, `100.00` when nothing was missed) feeding a `cacheHitPercent` that renders `99.50`-style strings; `formatCacheHitPercent` stays in `token-format.ts` for `TurnUsagePanel` (one decimal, unchanged). All 37 conflicted web snapshots resolve to the candidate's pill structure with our two-decimal values (taken from our side of each hunk, so they match the fixtures' exact ratios), plus our rewind labels where our side had changed them. `chat-stats.client.spec.tsx` adopts the candidate's pill assertions with our boundary table; the deleted `StatsLine` hover-tooltip test goes with the deleted component.

**Chat scroll.** `ChatView.tsx` takes the candidate's scroll refactor (sampled `onScroll`, `readerMovedScroll`, the memoized `ChatNodeList`, `realizePendingJump`/`loadThrough` jump re-anchoring) and keeps all of our paging behavior on top: `PAGING_TRIGGER = 2`, the short-window auto-page inside the layout effect, the three `loadOlderAnchored` continuation sites, and the `loadingOlderWasRef` true→false transition that clears the anchor (the candidate's jump settle tick owns the plain-pull jump interaction). `ChatNodeSeat`/`slots` carry both sides' props: our `rewindAt`/`openVersion` plus the candidate's `loadImage` and the new `useChatNode`/`useChatNodeProcess` seats.

**ModelSelect (functional collision, user-behavior rule applied).** Upstream added an `IconDataOutline16` database glyph with a 360px icon-only cut (its comment rationale references the effort-ellipsis row); we had a fish glyph with a 460px cut, synchronized with the sibling `PermissionSelect` chip and kept as a brand feature in the plan's acceptance list. Resolution: the fish glyph stays, the upstream 360px `.triggerIcon` block is dropped (it would double-declare the same property), the unused icon import is removed, and the 460px cutoff is retained.

**Providers documentation.** Both bullet sets survive: our detailed `reasoningEfforts` explanation plus the candidate's new "`off` does not stop a DeepSeek model from thinking / `compat.thinkingFormat: deepseek`" note, in both languages.

**Desktop runtime manifest.** `apps/desktop-runtime/package.json` is generated by `macos-app/scripts/stage-runtime.mjs` from three manifests plus a hand-maintained `WEB_PROFILE_PLUGINS` list; the list still named the fork-era `@deepseek-ai/dsh-tool-subagent-report`, which the candidate folded into `tool-subagent`. The stale entry was removed from the constant (the other 122 entries were each verified against the merged workspace) and the manifest was regenerated with the script's own closure logic — 221 dependencies at family version 0.1.5-alpha.2. `pnpm-lock.yaml` regenerates from the candidate baseline as purely additive importers (`apps/desktop-runtime`, `packages/web/web-search-ark`) with no third-party version movement.

**Web search settings API.** The candidate settings package dropped `installSettingsSection` in favor of `ctx.settings.installSection(owner, ns, schema, entry, hooks)` behind `ctx.inject(['settings'], …)`. The Ark provider's `apply` was migrated to that pattern (namespace is now a plain literal checked by the type system), matching the `llm-pi-ai`/`llm-deepseek` consumers.

**Spec expectation adaptations (§6.1 clean-clone `pnpm test`).** Two failures were stale expectations, not source defects, and both follow "change obsolete behavior with its tests":

- `chat-stats.client.spec.tsx`: the candidate's new dialog test expected an integer cache-hit percentage; the merged `StatsPills` renders the fork's two-decimal value, so the expectation is `90.00%`.
- `chat-view.client.spec.tsx` ("falls back to the first visible row when the viewport top hit-test misses"): a candidate-side test from the load-earlier-button era (upstream #3005). Fork commit `8088ba7f02` removed the button and updated three of its four click-driven tests but missed this one — it failed at the fork HEAD too (verified on a temporary worktree at `e28de3143c`). It now drives the merged paging gesture (reader arrival at the top via `scroll`/`scrollend`) and asserts the two synchronous `elementsFromPoint` hit-tests that one top-arrival delivery performs (the anchored paging capture and the continuous `chatScroll.save`) plus the relaxed row-rect budget of the two binary-search fallbacks.

**web-search-ark documentation conformance.** The fork-added package predates the candidate's documentation standard (the dsh-doc skill consolidation gates in `doc-standard.spec.ts`): its README pair was restructured onto the `package-reference` template skeleton (frontmatter `kind`/`description`, Summary / Table of Contents / Dev Note, and the 概述 / 目录 / 开发备注 equivalents), its config declaration was added to the generated `docs/config-catalog.md` (`gen-config-catalog`; the reviewed Chinese counterpart updated by hand and the pair re-recorded), and the zh side's locale links were pointed at the `.zh.md` targets. The fork's Ark-provider Agent Note needed the same locale-link fix on its zh side. All three pairs were re-recorded through `verify-translation-pairing --write`.

**§6.1 environmental triage (this Mac).** The remaining `pnpm test` failures reproduce with identical messages outside the merge's influence and are recorded as host-environment deviations, not merge defects:

- `terminal-bash` `local.spec` (6): `posix_openpt failed: Operation not permitted` — the pty device is denied to the session sandbox that ran the gate chain.
- `bash-local` `executor.spec` (1): the `mktemp`-based verify root is a `/var/folders/…` (non-canonical) path while the child `pwd` reports `/private/var/folders/…`; the assertion compares them for equality.
- `code-runtime-python` `runtime.spec` (238) and `boot-write-failure.spec` (6): the package loads only a CPython 3.10+ interpreter; the host default `python3` is 3.9.6 while `/usr/local/bin/python3` is 3.10.4 (the spec resolves `python3` through `PATH`).
- `run-gates.spec` abort/process-tree tests (6): process-group kill and reparenting semantics under the detached nohup chain.
- `transform-corpus.spec` (1): candidate-side. `tsx`'s tsconfig `paths` redirect the built dockkit bundle's bare `@deepseek-ai/dsh-client-ui-primitives` import to the source tree, so the sweep fails at `ui-primitives/src/StateDot.module.css` instead of the pinned baseline `ui-dockkit/lib/components/dockkit.module.css`. A candidate-only worktree at `b2e3b2a012` fails identically, and every corpus-relevant file (dockkit, the StateDot source, both package manifests, the tsconfig alias block, the spec and its pinned baseline) is byte-identical between the candidate and the merged tree.

## Alternatives considered

**Cherry-pick `756e2c3830` on top of the merge.** Rejected: it would re-introduce the fork-era uuid workaround next to the upstream mechanism it was superseded by.

**Side-for-side snapshot picks.** Rejected: picking our side wholesale would resurrect the deleted `StatsLine` structure; picking the candidate side wholesale would lose the two-decimal display, a user-visible feature of this integration.

**Keep both ModelSelect glyphs/cutoffs.** Rejected: two `.triggerIcon` declarations at different query breakpoints would fight over the same element; one glyph and one cutoff is the sibling-chip contract.

## Consequences

The merge commit carries the adapted behavior with the candidate as the structural base; the hgg save branch merges on top as its own merge commit. The §6.1 spec adaptations and documentation conformance land on the integration branch as their own commits and re-freeze the candidate SHA before any packaging. The touched bilingual pairs (two package READMEs, the providers guide, the Ark README pair, the config-catalog pair, the Ark-provider note pair, and this note) are re-recorded through `verify-translation-pairing --write` before staging. Candidate acceptance (§6) must still prove the assembled output: `test:gui`, the replayed `DSH_SNAPSHOT=replay test:web` lane, and the two isolated-platform App/`start-dsh-web.ps1` runs.
