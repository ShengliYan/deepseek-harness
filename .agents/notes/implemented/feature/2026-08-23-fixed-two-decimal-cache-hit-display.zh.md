# Agent Note：缓存命中固定显示两位小数

Status: implemented

[English](2026-08-23-fixed-two-decimal-cache-hit-display.md) | 中文

## Problem

[最小精度缓存命中显示](../../archived/feature/2026-08-19-high-cache-hit-decimal-display.md)让 100% 以下的每个比率都保持整数舍入，因此稳定在中段的数值（如 98.55%）会显示成 `98%`，用户逐条消息阅读时看不到百分比以内的变化。该策略只在接近满命中时提升精度，虽然保住了满命中的区分度，却让其余整个区间都比用户想看到的更粗。

## Decision

`cacheHitPercent` 现在以精确整数运算四舍五入到固定两位小数——比率乘以 20000 后，对一切现实可行的累计计数都保持在安全整数范围内——并且总是格式化出两位小数（`98.55`、`99.50`）。先前决策的满命中不变式得到保留：非满命中若两位小数舍入后到达 `100.00`，则封顶为 `99.99`；只有精确的完整命中才显示 `100.00`。计费输入为零时分组仍然省略。此决策完全取代最小精度策略；原拥有笔记已原样归档。

## Consequences

每个非空比率都携带相同的固定宽度，一个百分点以内的逐消息变化无需读取原始 token 计数即可见。介于 99.995% 与完整命中之间的比率一律显示 `99.99%`——旧变精度方案中最粗的一段——用这段尾部的区分度换来了统一格式。组件 spec 钉住含两条封顶分支在内的两位小数表，装配后的 `lifecycle-chrome` 回放显示 `99.50%`。

## Alternatives considered

**保留最小精度策略。** 否决：这正是本次修改要替换的行为——中段保持整数，一个百分点以内的逐消息变化依旧不可见。

**固定一位小数。** 否决：`98.55%` 会坍缩成 `98.6%`，在用户跨消息对比的粒度上重新引入可见舍入；两位小数即所要求的显示契约。
