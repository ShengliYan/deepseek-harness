# Agent Note：回退重发（版本化会话）

Status: implemented

[English](2026-08-16-rewind-and-resend-versions.md) | 中文

## 问题

用户想要 ChatGPT／Cursor 的「编辑并重发」手势：从任意问句气泡把对话回滚到那条问题，编辑后重发——同时保留上一次尝试，作为带编号的版本可随时切换（1/1 → 2/2，带左右箭头）。既有的两个 fork 入口都切在锚点所在轮次的末尾（子会话包含被点击的那一轮），无法表达「回退到这条问句之前」，版本导航也不存在。

## 决策

版本即 fork 会话。回退切出一个子会话，种子只含锚点轮次之前已完成的轮次，并把原始问题文本预填进子会话的输入框；源会话原封不动，作为上一个版本。会话列表的 fork 标题递增（`(1)`、`(2)`）天然提供版本号，`parentSessionId` 提供版本链。

Host：`session.fork` 增加可选 `rewind` 标志。`rewind: true` 且带 `atSeq` 锚点时，边界是严格早于「锚点所在轮次」的最后一个 `turn/end`；锚点位于第一轮时产出空子会话（空前缀是合法种子）。省略或越过日志末尾的锚点保持「最近已完成轮次」的捷径，普通 fork 的 fork-unavailable 拒绝保持不变。

客户端：runtime 的 `sessions.fork` 把 `rewind` 透传到线上。ui-conversation 的 `rewindAt(seq, text)` 注入以 `rewind: true` fork、打开子会话，并把 `text` 预填进其输入 shell。每个持久化用户气泡在复制旁渲染回退按钮（编辑图标，「从此处回退并编辑」/ *Rewind and edit from here*）；助手轮尾保留原有分支图标。

版本计数：版本只统计已提交的血缘成员。空白成员是待编辑的回退草稿（其重发轮次尚未落账），对谁也不计数——源会话保持 1/1，直到草稿的第一轮落账才翻到 1/2；草稿自身在落账前也不渲染任何翻页器。因此 `deriveVersionPager` 用 `!blank` 过滤血缘连通分量，索引取自已提交祖先链，挑选 `next` 时跳过空白子会话。

版本翻页器：会话标题栏中的 `‹ n/m ›` 控件（`conversation.session.header.actions`，order −10）。左箭头打开直接已提交父版本，右箭头打开最新已提交直接子版本；多子分叉点只打开最新子版本，其余兄弟仍可从侧边栏到达。

问句级切换器：每个持久化用户气泡在回退按钮旁渲染同样的 `‹ n/m ›`（单已提交版本时隐藏）。其箭头经 `openVersion(target, turn)` 路由：为目标会话记录一次待跳转并打开它；目标 ChatView 消费跳转并滚动到 `data-chat-turn`——轮次号跨版本共享（每个子会话都播种源前缀），因此跳转总是落在同一道问题上。读者由此比较同一问题下各版本产出的回答。

## 备选方案

**原地改写已排队／已投递的消息。**否决：已投递消息是持久日志事件（`Model-visible ⟺ logged`）；原地改写会篡改对话记录重建所依据的历史。fork 种子是「改写过去」唯一受支持的方式。

**在单会话日志内做版本图。**否决：日志是线性只追加流；版本图需要新事件词汇与非线性投影，而 fork 子会话已经让每个版本拥有独立、可搜索、可再 fork 的持久会话。

**自动分支树 UI。**暂缓：血缘连通分量可推导，但完整树是更大的界面；翻页器加既有侧边栏行已覆盖线性回退历史，即本次交付范围。

## 后果

每次回退都会新增一行会话（工作区列表中的同级行）并使 fork 标题计数递增；上一版本保持可打开，其自身回退点会产生兄弟版本。包级测试钉住回退边界映射（链中锚点、首轮空子会话、无锚点默认）、翻页器推导（根、最新子、兄弟、循环）与消息按钮接线；`apps/web/tests/message-actions.e2e.ts` 通过组装后的应用演练一次真实回退——子会话打开且问题已预填、翻页器显示 `n/m`、左箭头打开父版本——goldens 随用户气泡新按钮一并刷新。
